# V0.3 peptide ensemble analysis

## Scope

V0.3 summarizes all existing docking poses for one peptide across multiple
conformers. The A4 fixture contains 59 poses: conf01=20, conf02=19, and
conf03=20. V0.3 does not run Vina, modify source structures, perform RMSD
clustering, or batch-generate PSE/PNG files.

The implementation reuses the V0.2 raw-coordinate heavy-atom contact
primitive. The receptor monomer PDB is parsed once per run, and each
multi-MODEL PDBQT is parsed once into a real MODEL-label-to-block mapping.

## Contact definition

- direct: ligand/receptor heavy-atom minimum distance <= 4.0 Å;
- near: 4.0 Å < minimum heavy-atom distance <= 5.0 Å;
- none: minimum heavy-atom distance > 5.0 Å.

The receptor is the monomer PDB restricted to the chain named in the spec.
The ligand is the selected Vina MODEL PDBQT coordinate block. Hydrogen atoms
are excluded and distances are not rounded before classification.

## `legacy_5A_receptor_contact_fraction` audit

The existing pilot `analyze_results.py` defines the imported metric now named
`legacy_5A_receptor_contact_fraction` as:

> number of peptide residues having at least one ligand heavy atom within
> <=5.0 Å of any chain-A receptor heavy atom, divided by peptide length.

It is a whole-receptor interface breadth metric, not a target-residue contact
fraction. It uses the same unrounded heavy-atom `distance <= 5.0` loop as the
legacy target-contact field. The imported `legacy_basic_geometry_pass` embeds
`legacy_5A_receptor_contact_fraction >= 0.5`, legacy 5 A target-contact count
>=2, and zero receptor and chain-B clashes. It is therefore not a pure geometry
criterion.

V0.3 does not apply any contact-fraction hard filter. It retains
`legacy_5A_receptor_contact_fraction` as a secondary ranking criterion and
retains `legacy_basic_geometry_pass` only as provenance. Neither controls V0.3
eligibility.

## Eligibility and filter provenance

For each pose, V0.3 records independently:

- `receptor_clash_free`;
- `chain_B_clash_free`;
- `interface_eligible`;
- `representative_eligible`;
- every failed condition in `filter_reasons`.

The primary `selection_status` uses this priority:

1. `filtered_clash`;
2. `filtered_low_interface`;
3. `kept`;
4. `representative`.

Interface eligibility requires at least two formal direct target contacts and,
when configured, a hit in `required_any_direct_residues`. Representative
eligibility requires receptor-clash-free, chain-B-clash-free, and
interface-eligible status. A4 does not specify an artificial required-residue
set, and V0.3 does not invent a separate geometry criterion.

## Contact-pattern representatives

V0.3 groups representative-eligible poses within each conformer by their exact
direct-target-contact set. Pattern prevalence uses only representative-eligible
poses in that conformer as its denominator. Filtered poses are counted
separately as all-pose pattern frequency but cannot increase representative
ranking.

One pose wins within each pattern by legacy 5 A receptor contact fraction, Vina
score, minimum receptor distance, and MODEL label. Pattern winners are ordered
by direct contact count, eligible-pattern prevalence, and the same deterministic
tie-breakers. At most three contact-pattern representatives are emitted per
conformer.

This is contact-pattern diversity only. V0.3 does not calculate RMSD and does
not claim structural clustering or structural diversity.

## Frequency output

`target_contact_frequency.tsv` contains conformer-scope rows and peptide-scope
rows. Peptide rows include both raw 59-pose frequencies and conformer-balanced
frequencies. The balanced value is the arithmetic mean of the three conformer
frequencies, so conf02's 19 poses do not give it less influence than the two
20-pose conformers.

`conformer_presence_count` records how many conformers contain at least one
direct contact for a target residue. `recurrent_conformer_support_count` records
how many conformers meet the configured direct-contact frequency threshold
(0.25 for A4). The shared recurrent-direct core requires recurrent support from
every conformer; mere presence is insufficient.

## Outputs

- `pose_table.tsv`: one row per MODEL;
- `pose_target_contacts.tsv`: one row per pose and target residue;
- `target_contact_frequency.tsv`: raw and conformer-balanced frequencies;
- `conformer_summary.tsv`: per-conformer filtering and contact summary;
- `representative_poses.tsv`: selected contact-pattern representatives;
- `peptide_summary.json`: complete machine-readable summary and provenance;
- `peptide_summary.md`: human-readable summary;
- `run_manifest.txt`: input hashes, code hashes, MODEL inventories, and rules.

The dimer is validated and hashed but is not used to recalculate chain-B
metrics. Vina score, `legacy_5A_receptor_contact_fraction`, clash metrics,
minimum distances, and `legacy_basic_geometry_pass` remain imported from
existing pose-metrics TSV files.
