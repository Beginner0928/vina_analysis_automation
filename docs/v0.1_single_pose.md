# V0.1 single-pose automated reproduction

## Purpose

V0.1 reproduces one manually verified structure-analysis case:
`A4_conf02_out.pdbqt`, MODEL 1. It is a regression baseline for a future
parameterized workflow, not a generalized docking-analysis pipeline.

The analysis runs with the PyMOL 3.1.0 Python API in command-line/headless
mode. It does not run AutoDock Vina and does not modify source structures,
docking outputs, pose metrics, ligand protonation, or the manual report
package.

## Fixed inputs

The absolute input paths and expected values are stored in
`templates/A4_conf02_m1_golden.json`:

- TfR1 chain A receptor PDB;
- TfR1 AB dimer PDB, retained for provenance;
- `A4_conf02_out.pdbqt` with 19 Vina models;
- `A4_conf02_pose_metrics.tsv`;
- A4 sequence `SPSNFITMYDW`;
- manually confirmed target contacts and atom IDs.

The analyzer reads the original files in place. It calculates and records a
SHA-256 digest for each input.

## Golden data

The golden JSON is an immutable regression contract. It contains the expected
state count, target-contact set, model-1 score, contact fraction, three
distances, two angles, tolerances, and manual interpretation text.

If an automated result differs, investigate the program or input provenance.
Do not update golden values to make a failing run pass.

## Run

From the repository root:

```powershell
F:\aistuff\Conda\envs\pymol\python.exe scripts\analyze_single_pose.py
```

The analyzer refuses to run if
`test_output/A4_conf02_m1_v01` already exists. This prevents accidental
replacement of an earlier result bundle.

PyMOL's native PDBQT loader imports only the first model from this Vina output.
The analyzer therefore splits the existing `MODEL ... ENDMDL` blocks in memory
and loads them as 19 states with `cmd.read_pdbstr`. The original PDBQT is never
rewritten, and its atom IDs are preserved.

## Generated outputs

All runtime outputs are written beneath
`test_output/A4_conf02_m1_v01`:

- `A4_conf02_m1_measurements.tsv`: three atom-ID-based measurements;
- `A4_conf02_m1_contacts.tsv`: all target residues and 4 Å contact flags;
- `A4_conf02_m1_metrics.json`: machine-readable state, contact, measurement,
  and source pose-metrics data;
- `A4_conf02_m1_summary.md`: objective result summary plus the explicitly
  supplied manual interpretations;
- `A4_conf02_m1_interface.pse`: reproducible PyMOL session;
- `A4_conf02_m1_interface.png`: white-background 2400×1800 ray rendering;
- `run_manifest.txt`: versions, absolute paths, input hashes, and outputs;
- `validation_report.txt`: regression checks and final status.

TSV output is written with literal tab delimiters. Only the
Trp11 NE1–Gln160 OE1 distance is visible by default in the PNG; the other two
distance objects and both angle objects remain in the PSE but are disabled.

## Validate

```powershell
F:\aistuff\Conda\envs\pymol\python.exe scripts\validate_single_pose.py
```

The validator independently reads the golden JSON and generated TSV/JSON
files. It requires:

- exactly 19 states;
- an exact target-contact residue set;
- score within ±0.001 kcal/mol;
- distances within ±0.02 Å;
- angles within ±0.20°;
- contact fraction within the configured golden tolerance.

Any failed check produces `FINAL RESULT: FAIL` and a non-zero process exit
code. A complete match produces `FINAL RESULT: PASS` and exit code 0.

## Current limitations

V0.1 cannot:

- analyze a different candidate, conformer, model, receptor, or target site;
- prepare a ligand or change protonation states;
- run or rerun docking;
- infer a hydrogen bond from a 4 Å contact alone;
- infer affinity, BBB transport, transcytosis, or other biological activity;
- replace expert inspection or extend the supplied manual interpretations.
