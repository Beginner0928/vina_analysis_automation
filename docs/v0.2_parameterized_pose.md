# V0.2 parameterized single-pose analysis

## Scope

V0.2 analyzes one explicitly selected pose from an existing Vina multi-MODEL
PDBQT. It does not run Vina, modify input structures, infer peptide residue
chemistry, or search automatically for all hydrogen bonds.

The V0.1 analyzer, validator, documentation, and
`templates/A4_conf02_m1_golden.json` remain unchanged.

## Portable input spec

Committed specs use paths relative to the shared `competition` data root.
Pass the local location of that root at run time:

```powershell
F:\aistuff\Conda\envs\pymol\python.exe scripts\analyze_pose.py `
  --spec specs\A4_conf03_m1_v02.json `
  --data-root E:\research_related\competition `
  --output-dir test_output\A4_conf03_m1_v02_<run-id>
```

`--output-dir` must be inside this repository's `test_output` directory and
must not already exist. V0.2 has no overwrite option.

The equivalent Python API is
`analyze_pose(spec_path: Path, data_root: Path, output_dir: Path) -> Path` in
`scripts/analyze_pose.py`.

The machine-readable schema is `specs/pose_analysis_v02.schema.json`.
`input_sha256` is optional. If a hash is supplied, a mismatch is fatal. If it
is omitted, V0.2 still calculates and records the actual hash in
`run_manifest.txt` and `metrics.json`.

## Formal target-contact definition

For every target residue listed in the spec, V0.2 computes the minimum raw
floating-point distance over all ligand/receptor heavy-atom pairs. The
receptor is the monomer PDB explicitly restricted to `receptor_chain`; the
ligand coordinates are taken from the selected Vina `MODEL` PDBQT block.
Hydrogen atoms are excluded and distances are not rounded before comparison.

- `direct`: distance <= 4.0 Å
- `near`: 4.0 Å < distance <= 5.0 Å
- `none`: distance > 5.0 Å

The two cutoffs are fixed in V0.2 as `direct_contact_cutoff_A: 4.0` and
`near_contact_cutoff_A: 5.0`. PyMOL all-atom `within` selection is not used as
the formal contact criterion. `contacts.tsv` records the classification,
minimum distance, nearest ligand atom ID/name/PDBQT type, nearest receptor
atom name, and both cutoffs for every target residue. Near contacts remain
separate from direct contacts in `metrics.json`.

## MODEL semantics

`model` is the integer label in the PDBQT line `MODEL N`; it is not the
ordinal position of the block. V0.2 parses complete `MODEL ... ENDMDL` blocks
in memory, constructs an explicit MODEL-label-to-PyMOL-state mapping, and
fails if the requested label is absent or duplicated.

V0.2 deliberately does not rely on PyMOL's native PDBQT loader to create all
states.

## Manual interactions

`manual_interactions` contains only measurements supplied by the user. A
distance specifies a ligand atom ID plus receptor residue and atom. An
optional angle specifies ligand donor and hydrogen atom IDs plus the receptor
acceptor residue and atom.

When the list is empty, the ordinary pose/contact analysis still completes
and `measurements.tsv` contains only its header. Interpretations and ligand
labels are copied from the spec when present; V0.2 does not infer them.

## Outputs

Each successful run creates exactly this analysis package:

- `metrics.json`
- `contacts.tsv`
- `measurements.tsv`
- `summary.md`
- `interface.pse`
- `interface.png`
- `run_manifest.txt`

The JSON, summary, and manifest explicitly separate:

- values recomputed by V0.2: MODEL mapping/state count and raw-coordinate
  heavy-atom target contacts; PyMOL recalculates manual-spec distances/angles
  and creates the PSE/PNG;
- values imported from the existing pose-metrics TSV: Vina score, contact
  fraction, receptor clash/minimum distance, chain-B clash/minimum distance,
  and basic geometry pass.

The receptor AB dimer is validated and hashed for provenance and future
extension. V0.2 does not use it to recalculate chain-B clash metrics.

The existing pilot `pose_metrics.tsv` field `target_contacts` was generated
with heavy atoms at distance <= 5.0 Å. V0.2 therefore imports it explicitly as
`legacy_5A_target_contacts`. A legacy-only residue whose V0.2 distance lies in
the 4–5 Å near shell is classified as `EXPECTED_DEFINITION_DIFFERENCE`, not a
warning. Only a difference that cannot be explained by the direct/near versus
legacy 5 Å definitions is recorded as `WARNING_MISMATCH`; neither status
overwrites the independently recomputed direct and near results.
