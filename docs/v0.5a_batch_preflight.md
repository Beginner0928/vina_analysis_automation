# V0.5-A deterministic batch planner and preflight

V0.5-A adds a validation and planning layer around the scientific behavior
frozen at release `v0.4`. It does not run AutoDock Vina, prepare new ligands,
generate conformers, aggregate screening results, or change any V0.4 contact,
eligibility, representative-pose, or scoring definition.

## Frozen contracts

- `specs/top40_candidates_v05.json` is the canonical machine-readable identity
  contract for exactly A1-A10, B1-B10, C1-C10, and D1-D10. Candidate records
  contain only identity fields and the asserted peptide length.
- `specs/top40_ligand_inventory_v05.json` represents every conformer slot
  required by the protocol. Missing inputs are explicit and never inferred as
  ready.
- `specs/screening_protocol_v05.json` freezes the V0.4 ligand-preparation and
  Vina settings, the required conformer names, the one-process concurrency
  policy, and the hashes of external and Git-managed provenance contracts.
- `requirements-v05-lock.txt` is the verified Windows CPython 3.12 runtime lock.

The original TSV, CSV, FASTA, and XLSX candidate sources are recorded as audit
provenance, but are not runtime prerequisites after the canonical JSON is
frozen.

## Current inventory truth

The inventory contains 120 protocol-derived slots (40 candidates by three
formal conformers):

- A4: three `approved_for_formal_screening` slots.
- B3: three `approved_for_formal_screening` slots.
- C2: three `conversion_audit_only` slots.
- D8: three `conversion_audit_only` slots.
- The other 108 slots: `not_prepared`.

Accordingly, a dry-run for A4 or B3 can pass. Full A/B and C/D dry-runs are
expected to return `DRY_RUN_FAIL_CANDIDATE` until all selected candidates have
approved formal inputs. This is an accurate readiness result, not a docking or
scientific-quality judgment.

## CLI

Run with the chemistry/project Python 3.12 environment. The output path must
not already exist, and dry-run does not create it.

```powershell
python scripts/run_batch_v05.py `
  --manifest specs/top40_candidates_v05.json `
  --protocol specs/screening_protocol_v05.json `
  --data-root E:\research_related\competition `
  --output-root E:\research_related\competition\planned_runs\ab_v05 `
  --vina E:\research_related\competition\tools\AutoDockVina\vina.exe `
  --groups A B `
  --dry-run
```

The formal workstation allocation is teammate workstation = groups A+B and
Roy/primary workstation = groups C+D. Explicit subsets use `--candidates`, for
example `--candidates B3 A4`; the emitted plan remains in canonical manifest
order (`A4`, then `B3`) regardless of command-line order.

Exactly one of `--groups` and `--candidates` is required. V0.5-A deliberately
does not expose flags for resume, real execution, failure policy, attempts, or
aggregation.

## Dry-run guarantees and results

Dry-run validates the candidate manifest, ligand inventory, protocol, schemas,
raw hashes, receptor registry, chemistry contract, Git release identity,
runtime lock, Vina executable identity, output collision, registry resolution,
ligand artifacts, frozen chemistry, comparison-protocol derivation, generated
runtime specs, and deterministic projected paths.

Vina identity is established from the frozen executable SHA-256. The executable
is not started. The result includes `vina_docking_process_count: 0`, and unit
tests forbid both `subprocess.run` and `subprocess.Popen` during this check.

Stable outcomes and process exit codes are:

- `DRY_RUN_PASS`: 0
- `DRY_RUN_FAIL_GLOBAL`: 2
- `DRY_RUN_FAIL_CANDIDATE`: 3

Failures contain candidate (or null for global checks), phase, error code, and
message. A failed dry-run does not emit a success-looking production package.

`SourceConformerID` remains provenance metadata from the approved standardized
SDF contract. V0.5-A treats it as opaque and does not reinterpret it as an
RDKit internal conformer index.

## Later stages not implemented here

V0.5-B/C/D will separately define real execution, resume/failure behavior,
immutable attempts, completion markers, aggregation, cross-workstation merge,
and control docking. None of those behaviors is present in V0.5-A.
