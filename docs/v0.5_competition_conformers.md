# V0.5 Top40 competition conformer generation

This subsystem defines a new ligand-generation lineage for uniform Top40 exploratory screening. It does not reuse historical A4, B3, C2, or D8 conformers and does not run Meeko, AutoDock Vina, docking analysis, or batch execution.

## Scientific scope

The frozen protocol ID is `tfr1_top40_sdfgen_competition_v1_b3derived`, classified as `COMPETITION_EXPLORATORY_SCREENING`. It supports reproducible within-protocol competition comparisons. It is not exhaustive conformational sampling, an experimentally validated ensemble, or a final validated peptide conformational protocol.

Candidate identity comes only from `specs/top40_candidates_v05.json`. The generator verifies its locked raw-byte SHA-256 before reading candidate ID, group, sequence, and sequence-validated length. Historical SDFs are neither inputs nor fallbacks.

## Chemistry contract

The generator verifies and applies the frozen `v04_formal_standardized_peptide_chemistry` contract:

- protonated N terminus and deprotonated C terminus;
- deprotonated Asp/Glu and protonated Lys/Arg;
- neutral HIE-like histidine with NE2 protonated and ND1 unprotonated;
- reduced neutral Cys-SH and neutral Tyr-OH;
- standard L amino-acid stereochemistry;
- no artificial disulfide bonds.

Before embedding and after every SDF read-back, the workflow checks sequence, length, formal charge, atom and heavy-atom counts, heavy-atom bond graph, stereochemistry, termini, residue protonation, and the absence of S-S bonds. Audit failures are fatal and are not repaired after generation.

## Frozen generation and selection

The exact environment and parameters are in `specs/competition_conformer_protocol_v1.json`:

1. RDKit 2026.03.6 builds the standardized peptide.
2. The candidate seed is `1 + (int(SHA256((protocol_id + ":" + candidate_id).UTF8)[0:8], 16) mod 2147483646)`.
3. ETKDGv3 requests 30 source conformers with random coordinates, pruning at 0.25 A, chirality enforcement, and one thread.
4. MMFF94s optimizes each source conformer for at most 1000 iterations on one thread.
5. Only convergence status 0 enters selection. There is no UFF, unconverged, historical, or alternate-embedding fallback.
6. Eligible conformers are ordered by MMFF94s energy and then original RDKit conformer ID.
7. `conf01` is the lowest-energy eligible conformer. The algorithm greedily adds candidates that satisfy the active distance threshold against every already selected conformer.
8. A fresh full-set attempt is made at 2.0, 1.5, 1.0, then 0.5 A. The highest threshold that yields three conformers is used. Failure at 0.5 A is fatal.

RMSD uses heavy atoms only, fixed identical atom indices, and optimal rigid-body alignment through `rdkit.Chem.rdMolAlign.GetAlignmentTransform`. Hydrogen atoms are excluded. `SourceConformerID` is always the original RDKit ID; `FormalConformerOrdinal` is separately `conf01`, `conf02`, or `conf03`.

## Commands

Production generation is deliberately explicit and all-or-nothing:

```powershell
<PROJECT_PYTHON> scripts\generate_competition_conformers.py `
  --protocol specs\competition_conformer_protocol_v1.json `
  --data-root <DATA_ROOT> `
  --all
```

It writes only to `<DATA_ROOT>/standardized_ligands/<protocol_id>` and refuses an existing directory. There is no force/overwrite option. Running this all-40 command requires separate scientific approval.

The dedicated software smoke command always selects canonical A4 and B3 and requires a fresh external root:

```powershell
<PROJECT_PYTHON> scripts\smoke_competition_conformers.py `
  --protocol specs\competition_conformer_protocol_v1.json `
  --data-root <DATA_ROOT> `
  --smoke-root <EXTERNAL_SMOKE_ROOT>\run01
```

Audit is read-only:

```powershell
<PROJECT_PYTHON> scripts\audit_competition_conformers.py `
  --protocol specs\competition_conformer_protocol_v1.json `
  --data-root <DATA_ROOT> `
  --protocol-directory <EXTERNAL_SMOKE_ROOT>\run01\tfr1_top40_sdfgen_competition_v1_b3derived
```

## Output and provenance

Each candidate directory contains three SDF files. The protocol directory also contains `preparation_manifest.json`, `generation_summary.tsv`, and `SHA256SUMS.tsv`. SDF properties include the candidate/chemistry identity, environment, deterministic seed, source/eligible counts, original source conformer ID, MMFF energy/status, selection threshold, all three pairwise RMSDs, and graph/stereochemistry hashes.

An SDF never contains its own raw-byte SHA-256. Each raw SDF hash is published externally in both `preparation_manifest.json` and `SHA256SUMS.tsv`. The audit requires those hashes to agree with actual bytes, validates all required properties, and reruns the chemistry checks.

Raw SDF packages must remain outside Git. The repository stores only the code, protocol/schema, tests, and documentation needed to reproduce them.
